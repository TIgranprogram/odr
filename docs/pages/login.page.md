# Страница: Вход (Login)

- **Маршрут:** `/login` · **Компонент:** `frontend/src/app/features/auth/login.component.ts`
- **Доступ:** публичный (единственный экран без `authGuard`).

## Назначение
Аутентификация пользователя по логину и паролю. При успехе сохраняются
`accessToken`/`refreshToken` и пользователь; выполняется переход в shell.

## UI-действия
| Элемент | Действие | Результат |
|---|---|---|
| Поле «Логин» | ввод | обязательное поле формы |
| Поле «Пароль» | ввод | обязательное поле формы |
| Кнопка «Войти» | submit | `POST /api/auth/login`; при успехе — редирект на `/requisitions` |
| Ссылка/кнопка регистрации | — | отсутствует (регистрация только для ADMIN на бэкенде) |

## API
| Метод | Путь | Когда |
|---|---|---|
| POST | `/api/auth/login` | submit формы; тело `{ username, password }` |

## Уведомления и ошибки
- Кнопка блокируется во время запроса (`loading`) и при невалидной форме.
- `401` — неверные учётные данные; `429` — превышен лимит попыток (10 / 15 мин).
- Ошибки отображаются на экране (interceptor для `/login` не делает refresh).

## Связи
- Успех → `AuthService` (`core/`) сохраняет токены → `authGuard` пускает в shell.
- Истёкший access-токен в дальнейшем обновляется через `POST /api/auth/refresh`.
