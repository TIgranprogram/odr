# CURRENT_STATE (Save Game)

> Это файл «сохранения» проекта. Я обновляю его после каждого значимого этапа, чтобы мы могли продолжить работу даже при потере контекста.

## 📍 Текущий статус
**Этап:** Архитектурное планирование и инициализация документации.
**Статус:** В процессе разработки структуры документации.

## 🔄 Последнее действие
Проведен аудит архитектуры старого проекта (`D:\kppdf-8.0`), выбраны лучшие практики (State Management, Domain Map, Integrity Slots) и сформирован план документации.

## ⏭️ Следующие шаги
1. Заполнение `ROADMAP.md` (разбивка на этапы: Инфраструктура, Снабжение, Аналитика).
2. Заполнение `DOMAIN_MAP.md` (сопоставление модулей бэкенда и страниц фронтенда).
3. Заполнение `TECH_STACK & GUIDELINES.md` (на основе архитектурного аудита).
4. Инициализация структуры папок `/backend` и `/frontend`.

## 📝 Контекст и решения
- **Используем State Management:** Каждый раз обновляем `CURRENT_STATE.md`.
- **Snapshot Immutability:** Будем использовать концепцию неизменяемых снимков данных при переходах статусов (чтобы история не менялась при правке справочников).
- **Domain Map:** Вводим обязательную карту доменов для быстрого поиска связей.
- **Инфраструктура:** Используем NestJS (BE), Angular 17+ (FE) и MongoDB.
